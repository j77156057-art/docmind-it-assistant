# 企业级实施路线图

## 当前基线

当前版本是独立的查询型最小产品：FastAPI、Markdown 知识、SQLite 历史、确定性检索、模型路由元数据和 Token 计价。它可以本地演示，但尚不等同于生产级 RAG 平台。

## 分阶段计划

| 阶段 | 目标 | 主要交付物 | 验收条件 |
|---|---|---|---|
| P0 工程底座 | 建立可持续交付能力 | ~~配置校验、结构化日志、健康检查、依赖锁、PostgreSQL Repository、Alembic~~；待完成应用容器、CI | 全新环境可重复构建；测试和安全扫描自动执行 |
| P1 身份与数据 | 建立企业数据边界 | PostgreSQL、Alembic、OIDC、RBAC、查询/审计表 | 未认证不可查询；不同角色无法互读受限知识 |
| P2 知识链路 | 建立正式 RAG | ~~文档解析、版本、分块、pgvector、全文 + 向量 RRF~~；待完成 ACL、重排和发布回滚 UI | 文档可增量发布与回滚；引用可定位到版本和页码 |
| P3 模型网关 | 建立真实模型调用 | ~~Provider Client、超时重试、Token/费用账本~~；待完成预算、熔断和降级 | 主模型故障时自动回退；密钥不出现在接口或日志 |
| P4 管理后台 | 独立维护知识 | 导入、审核、ACL、发布、评测和作废流程 | 查询用户没有管理入口；所有管理动作可审计 |

## 质量门

- 所有查询必须具有 `request_id`，跨 API、检索、模型和数据库可关联。
- 所有返回知识结论必须至少有一个授权引用。
- 未找到授权证据时必须拒答，不能仅靠模型常识补全。
- 单元、集成、端到端和安全测试均通过后才能发布。
- 数据库迁移必须同时提供升级与恢复方案。
- 任何新增执行权限必须先更新隔离文档并经过安全评审。

## 主要风险

| 风险 | 控制方式 |
|---|---|
| 文档越权泄露 | 检索前 ACL、租户过滤、越权自动测试 |
| 提示词注入 | 文档内容视为数据、系统规则不可被文档覆盖、输出引用校验 |
| 模型费用失控 | 累计预算、分钟限流、供应商配额和告警 |
| 文档版本混乱 | 内容哈希、发布状态、原子切换和回滚 |
| 低质量回答 | 企业黄金题、召回指标、拒答率和用户反馈闭环 |
| 服务故障 | 无状态查询实例、熔断降级、备份与恢复演练 |
